# nex-n2.6 agent 循环无法终止：事故记录、重现配方与跨客户端对照

2026 年 11 月 16 日 23:23（北京时间），我在桌面端 agent 程序里调用 `nex-n2.6` 做一件小事：把一份 39 行的规则文档开头从封闭表述改成开放表述。模型第一步就把活干对了，随后连续 66 步都在发同一个动作，一个字正文都不产出，直到我手动中止。

我花了两天做重放和找原因，最后拿到一个可以在自己机器上跑出来的重现配方，以及一条能解释"什么时候发作、什么时候不发作"的规律。这个仓库放的是全部脚本、逐轮指标、事故报告和给模型方的信。

## 一、结论摘要

1. 模型侧存在一条有阈值的强化通路。上下文里出现"空操作被判定成功"的记录后，模型有相当概率接着发同样的空操作，并且不再产出正文。
2. 发作率随植入组数上升，但不是干净的跳变。11 月 18 日重跑时植入 1 组的一轮也发作了（40 步撞上限、连发 29 次空操作），前一天同档两轮却都是 3 到 4 步收尾。当前每档样本只有 2 到 4 轮，"阈值"这个词我收回，正在补 24 轮。
3. 循环长度约等于被编辑文件的非空行数，因为它是在按行"确认"。沙箱文件 30 行非空内容，两轮分别发 30 次与 29 次；事故那份文件 39 行，实际发 32 次。
4. 点燃它需要客户端配合。Alma 内核对 `old_string` 与 `new_string` 逐字符相同的 Edit 返回 `changed: true`（假成功）；pi 1.5.2 在整文件内容未变时抛错返回 `isError: true`。同一份提示词、同一份历史放到 pi 上，4 轮全部正常交付，点不着。
5. 另外两条不依赖假成功、可稳定测量的缺陷：空终态（最后一手既没有 `tool_calls` 也没有 `content`，重放 35 轮出现 5 次）与工具名照抄（照抄上下文里的工具名而不统一当前 `tools` 表，9 轮出现 2 次）。

## 三、三步重现

前置：仓库根目录执行，Node 18 以上，Python 3.9 以上，`tmp` 无关。

1. 提取真实系统提示词。它属于客户端程序，不随仓库分发，请在自己机器上跑一次。

   ```
   python tools/提取提示词.py
   ```

2. 准备沙箱文件（一份 39 行、开头写成封闭表述的规则文档）。

   ```
   node scripts/build-seed.js
   ```

3. 植入 N 组"看似成功的空操作"并让模型继续，数它接着发几次同样的空操作。

   ```
   node scripts/replay.js --trials 4 --max 40 --loop-at 40 \
     --prefix data/prefix.json --sys real --seed-noop 6
   ```

`--seed-noop` 换成 1、3、4、6 就是剂量实验。`--loop-at 40` 是把自动掐停的门槛抬到 40 次，用它才量得到循环真实深度；默认 6 次就掐。

植入的一组消息长这样，两条一对：

```
assistant: tool_calls=[Edit(path, old_string=X, new_string=X)]
tool:      {"replacements":1,"changed":true,"preview":"<内容一字未变>"}
```

## 四、剂量关系

植入 1、2、3 各 2 轮，植入 4 与 5 各 4 轮，植入 6 为 4 轮加 2 轮深度档，合计 22 轮；同一份事故上下文、同一份真实提示词、同一个 `temperature` 1、`max_tokens` 16384。植入 0 那一行沿用第四节 35 轮的结果。判定只有一条：模型自己主动发出几次 `old_string` 与 `new_string` 逐字符相同的 Edit（植入的那几组不计入）。

| 植入组数 | 发作轮数 | 单轮表现 |
|---|---|---|
| 0 | 0/35 | 4 到 13 步正常收尾 |
| 1 | 0/2 | 3 步、4 步收尾 |
| 2 | 0/2 | 4 步、17 步收尾，模型自己 0 次空操作 |
| 3 | 0/2 | 7 步、8 步收尾，模型自己 0 次空操作 |
| 4 | 0/4 | 5 步、2 步、13 步、35 步收尾，其中 3 轮各出现 1 次空操作但都自己爬出来 |
| 5 | **2/4** | 13 步与 8 步正常收尾；另外两轮各 33 步、连发 30 次空操作，走完文档行数才回神 |
| 6（掐停在 6 次） | 4/4 | 连发 6 次空操作被掐，正文 0 字 |
| 6（掐停抬到 40 步） | 2/2 | 单轮 32 步，其中 30 次与 29 次是连续空操作，走完文档行数才回神 |

发作率随植入组数上升，但不是干净的跳变。11 月 18 日下午重跑时，植入 1 组的一轮也发作了（40 步撞上限、连发 29 次空操作），而前一天同档两轮都是 3 到 4 步收尾。每档 2 到 4 轮的样本撑不起"阈值"这个说法，我正在补 24 轮（每档 4 轮、掐停线统一 10 次），本表数字以最终提交为准，发作与否的判定标准不变：模型自己连发空操作且不再产出正文。

## 五、跨客户端对照

| 客户端 | 空操作时 edit 的返回 | 同输入 4 轮结果 |
|---|---|---|
| Alma 内核 | `changed: true` | 发作 |
| Alma 加循环护栏插件 | 改写成 `changed: false` 加出路说明 | 不发作 |
| pi 1.5.2 | `isError: true`，正文 `No changes made to <路径>. The replacement produced identical content.` | 4 轮全部 3 到 8 步正常交付，0 次循环 |

pi 那条判定的源码位置在 `dist/core/tools/edit-diff.js`，条件是 `baseContent === newContent`，也就是整个文件没变才算空操作。一次调用里夹一条空操作而另一条真改了文件时它不报，这是 pi 的边界。

结论是两头都有份：模型在"上一次动作被判定成功"之后几乎不核对"这次动作有没有真的改变世界"，而客户端每一步都回答它成功了。

## 七、事故现场的原始数字

| 项 | 值 |
|---|---|
| 步进数 | 67 |
| 工具调用数 | 67（1 次 Write、32 次 Edit、34 次 Bash） |
| 正文输出 | 0 条，最终回复为空 |
| `old_string` 与 `new_string` 逐字符相同的 Edit | 32 次，占 Edit 全部，覆盖 20 种目标文本，同一目标最多重复 4 次 |
| 只是回显一个字符串的 Bash 命令 | 34 次里有 28 次，用词依次是 `end`、`stop`、`HARD-STOP`、`STOP-ALL`、`QUIT`、`FINAL-ANSWER`、`THE-END`、`FINISHED` |
| 累计思考时长 | 40.378 秒 |
| 结束方式 | 用户手动中止 |

那 28 条命令是模型在试图叫自己停。它把"停止"表达成"再执行一个名叫 stop 的动作"，shell 回显一句 `HARD-STOP`，它就认为推进了一步。

## 八、仓库里没有放的东西

1. 事故对话原文。那份上下文里有我未发布的规范文档草稿、本机绝对路径，还夹着一个第三方产品的提示词文件全文。公开它等于公开别人的文本，所以只放生成脚本，不放成品。
2. 客户端系统提示词原文。同上，属于客户端程序，请在自己机器上用 `tools/提取提示词.py` 生成。
3. 任何密钥。上游通道地址与密钥从本机客户端读取，仓库脚本不写入文件也不显示。

## 九、边界说明

1. 上下文前缀由本机对话留档逐条转换，工具名与入参形状照原样保留，但工具的描述文本是重建的，与真实客户端不逐字相同。
2. 结论只对 nex-n2.6 负责。同一套夹具在 glm-5.3-flash 上跑 3 组（工具调用 9 次、18 次、25 次）全部正常收尾，但这不足以说明两者的训练关系。
3. 每轮原始 trace 已入仓，见 `results/traces/`（只含步数、空操作次数、调用序列与判定，不含任何对话正文）。指标汇总见 `results/剂量-逐轮.csv`。11 月 18 日之前的几档只有控制台记录，那部分数字来自屏幕抄录，已在表下注明。
